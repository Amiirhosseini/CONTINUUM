Core Differentiation

Why CONTINUUM is built differently from traditional memory and workflow tools.

01

Semantic Checkpoints

Not a full conversation dump. Extracts minimal verified task state (goals, decisions, findings, evidence) into a versioned, inspectable tree.

02

Independent State Validation

Never blindly trusts old checkpoints. Compares saved state against live environment (file hashes, dataset versions, permissions) before resuming.

03

Idempotent Action Ledger

Remembers external side effects (API calls, GitHub writes). Intercepts duplicate calls on recovery and returns original cached results.

04

Tamper-Evident Event Log

Append-only SHA-256 hash-chained event log. Provides verifiable provenance and exact sequence auditing for every state component.

05

Recovery Contracts

Generates deterministic machine-readable contracts specifying state validity, invalidated items, and next allowed recovery actions.

06

Framework-Agnostic & CPU-First

Runs locally with SQLite and Pydantic v2. Zero external cloud dependencies, zero mandatory model downloads, zero GPU required.

Quickstart & API

Simple, clean Python SDK interface for long-running agent state persistence.

# Python SDK Quickstart
from continuum import Continuum

# Initialize local SQLite storage
runtime = Continuum(storage="sqlite:///agent.db")

# Start a run
run = runtime.start(goal="Analyze 10,000 research documents")

# Record progress and findings
run.record_finding(claim="Strong correlation observed", confidence=0.94)
run.update_progress(completed=3421, pending=6579)

# Checkpoint semantic state
run.checkpoint()

# Record external side effects safely
run.record_action(type="github.create_issue", arguments={"title": "Bug found"})

# Resume after crash
recovered_run = runtime.resume("run_4821")
status = recovered_run.validate()

if status.safe:
    recovered_run.continue_execution()
